# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FurBrainsAR is a mobile AR prototype built on Unity's **Mobile AR template** (Unity 6.3 LTS, `6000.3.28f1`). Its primary target is **Android (ARCore)**; ARKit is installed but iOS isn't currently built.

## Product context

**FurBrains** is a fluffy AI toy for children aged 3–11 that they can talk to. This app lets the player interact directly with a **digital FurBrain** in AR. It is **one app** that combines two things:

1. **AR pet game (the core loop):** a virtual pet that lives in the player's space (care, feeding, play, a growing relationship), in the genre of AR virtual-pet games.
2. **A broad minigame collection played with the FurBrain:** this is the key differentiator. Pet games in this genre usually offer only a small selection of minigames, while FurBrains should offer many. Architect minigames as **pluggable modules** sharing a common interface (start/end, results feeding back into the pet's state) so new ones are cheap to add.

Design implications:
- **The audience is young children.** Use large touch targets, minimal reading (icons, audio, animation), simple one-finger gestures, short sessions, and no fail states that punish.
- **Child privacy:** treat camera and microphone data and any voice or AI features with child-privacy rules in mind (e.g. COPPA, GDPR-K). Don't add analytics, ads, accounts or network calls without discussing it first.
- The FurBrain character is the toy's own IP. Mechanics can draw on the genre, but don't copy specific existing games' characters, art or content.

## Working with the user

- They have some Unity experience and are strongest in **C++**, and they're new to C#-heavy Unity work and to Claude Code. Explain C#/Unity concepts by comparison with C++ where it helps: GC vs. manual lifetime, `Destroy()` vs. `delete`, MonoBehaviour lifecycle vs. constructors, properties, events/delegates, `[SerializeField]`.
- They want to **understand how the project works**, not just get working code. For each change, briefly explain what was changed, why, and how it fits into the existing architecture (which components talk to which, and what's wired in the scene vs. in code). Point to the relevant files rather than treating code as a black box.
- Spell out any Editor steps that code changes depend on.
- **Keep code simple.** The user is a graduate and wants to follow every new feature. Prefer plain, direct code using the core OOP principles (encapsulation, abstraction, inheritance, polymorphism) where they fit naturally (e.g. the `Minigame` base class, `IconButtonMenu`).
- **Ask before adding design patterns** or less obvious practices (e.g. publisher/subscriber events, state machines beyond a simple enum + switch, dependency injection, object pooling). If one would clearly help, briefly explain what it is and why, and let the user decide. The plan is to build features simply first, then introduce patterns once they're understood, for more efficient, reusable code in the long term.

Key packages (see `Packages/manifest.json`): AR Foundation 6.5, ARCore/ARKit 6.5, XR Interaction Toolkit 3.5.1, Input System 1.20, URP 17.3, Android Logcat.

## Working with the Unity Editor

- The user normally has the project open in the Editor. Unity recompiles C# when the Editor regains focus, and compile errors show in the Editor **Console**. Ask the user to paste them.
- Scene and prefab wiring (adding components, assigning serialized references, UnityEvent hookups) is usually quickest done by the user in the Inspector. Give exact steps. Editing `.unity`/`.prefab` YAML directly is possible (serialization is Force Text) but fragile: references use fileID/GUID pairs from `.meta` files.
- Every asset has a `.meta` file holding its GUID. When creating, moving or renaming assets, keep the `.meta` alongside, or let Unity generate it. Never regenerate or delete a `.meta` for an existing asset, because that breaks references.
- Batch-mode commands (`Unity.exe -batchmode -projectPath ...`) fail while the Editor has the project open.
- Editor path: `C:\Program Files\Unity\Hub\Editor\6000.3.28f1\Editor\Unity.exe`.
- adb (not on PATH): `C:\Program Files\Unity\Hub\Editor\6000.3.28f1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe`. Device logs: `adb logcat -s Unity`, or the Android Logcat window in the Editor.

## Build & test

- Builds are made from the Editor (**File → Build Profiles → Android → Build / Build And Run**) into `Builds/Android_Build/`, which is git-ignored. There is no scripted build pipeline.
- Only `Assets/Scenes/SampleScene.unity` is in the build scene list.
- In-Editor Play mode uses **XR Simulation** (the Standalone loader), so AR features can be tested without a device. Real plane tracking, lighting and performance need an on-device build.
- There are no automated tests yet. Unity Test Framework is available through `com.unity.feature.development`.

## Architecture

The app is the template's `SampleScene`: tap a detected plane to place an object, then move, rotate or scale it.

- **XR Origin (AR Rig)** (`Assets/Samples/XR Interaction Toolkit/3.5.1/AR Starter Assets/Prefabs/`) contains the AR camera, the AR managers (planes, raycasts) and a screen-touch `XRRayInteractor` fed by XRI touchscreen gesture input. Placed objects are XRI interactables (the prefab variants in `Assets/MobileARTemplateAssets/Prefabs/`, such as `CubeVariant`), so move, rotate and scale come from XRI, not custom code.
- **Placement flow:** `ARInteractorSpawnTrigger` waits for a tap that doesn't select anything, raycasts against AR planes (ignoring taps over UI), and fires `objectSpawnTriggered(position, normal)`. In the scene, that event is wired to `ObjectSpawner.SpawnObject`, which instantiates from its `objectPrefabs` list (7 entries, set in the scene) and, with `spawnAsChildren`, parents spawned objects under the spawner. `spawnOptionIndex = -1` means random.
- **`ARTemplateMenuManager`** (`Assets/MobileARTemplateAssets/Scripts/`) owns the UI. The create menu's buttons call `SetObjectToSpawn(index)`, which sets the spawner index. It also handles deleting the focused object (via `XRInteractionGroup.focusInteractable`), "clear all" (destroys spawner children), plane-visualization toggles (adds `ARPlaneMeshVisualizerFader` to new planes) (FurBrains: `SetPlanesVisible`, called when a FurBrain is summoned (hide) or deleted (show), polling `FurBrainSummoner.hasSummoned` in `Update`) and the AR debug menu.
- **`GoalManager`** runs the onboarding prompt sequence (greeting → scan surfaces → tap to place → move/rotate/scale hints) using the `Prompt_*` prefabs in `Assets/MobileARTemplateAssets/UI/Prefabs/`.
- Input comes from the Input System via `XRI Default Input Actions.inputactions`. Scripts read it through XRI `XRInputValueReader`/`XRInputButtonReader` fields, not legacy `Input.*`.

## FurBrains character pipeline

Characters come from the other team's **Unreal Engine** project. All FurBrains characters share one **UE5-mannequin-based 100-bone skeleton** (plus `Ear_*` ×4 per side and `Cape*_001` ×4), so animations are shareable between characters. Faces use **blend shapes** (emotions, `Blink`, visemes `A I U E O`), not jaw or face bones.

- **Characters are modular:** each is several skeletal-mesh FBX parts (Body, Mouth, Eyebrows (actually the eyes), Helmet_Armor, Armor, Cape for Ziara), exported one by one from the character Blueprint's components. Unreal materials and Physics Assets don't transfer; textures do.
- **Import settings for part and animation FBX:** cameras, lights and empty "Unreal Take" animations off; **Generic** rig (Humanoid would drop the ear and cape bones). Animation-only FBX: no materials.
- **Editor tools** (`Assets/FurBrains/Editor/`, editor-only):
  - `FurBrainsTexturePostprocessor`: every texture under `Assets/FurBrains/` is capped at 2048 with ASTC on Android; `*normal*` → normal map, `*roughness*/*alpha*/*mask*` → linear. Anything under `Assets/FurBrains/UI/` imports as a transparent Sprite without mipmaps (the UI icons live in `UI/Icons/`: white on transparent, so they can be tinted with the Image colour). Anything in `UI/Shapes/` also gets a 9-slice border of half its size: `Shape_Round.png` (64 px circle) drawn Sliced makes any pill or rounded box, with radius = 32 / the Image's Pixels Per Unit Multiplier.
  - `FurBrainsModelPostprocessor`: per-file mesh repairs at import (Ziara's right eye is inside-out in the source FBX and is flipped here).
  - `FurBrainsMaterialBuilder` (**Tools → FurBrains → Create Ziara Materials**): builds URP Lit materials from the texture names, merges Unreal's separate `_Alpha` masks into `*_Cutout.png` for alpha clipping, and assigns them via the FBX importer's material remaps. The slot → texture table is hand-written per character.
  - `FurBrainsCharacterBuilder` (**right-click selected part FBX → FurBrains → Build Character Prefab**): keeps the Body's skeleton, rebinds every other part's `SkinnedMeshRenderer.bones` to it by bone name (Unity's equivalent of Unreal Leader Pose), trims surplus material slots, adds `FurBrainFace`, and saves `<Folder>.prefab`. Run it **after** the materials tool.
- **`FurBrainFace`** (`Assets/FurBrains/Scripts/Character/`): sets blend shapes **by name across all parts** (the same shape exists on several parts, e.g. `Happy` on Body and Mouth), eases weights, auto-blinks, and applies in `LateUpdate` so it overrides animation clips.
- **Fur:** Unreal uses a Groom (strand hair), which doesn't export and is too heavy for mobile. The current look is texture-only: **Tools → FurBrains → Add Fur Texture To Ziara** (`FurBrainsFurTextureMaker`) builds a flow map from Ziara's rest-pose mesh (gravity flattened onto each triangle, converted to texture space), draws combed, clumped strands along it, and bakes them into `Models/Ziara/Rabbit_Body_BaseColor_Fur.png` (brightness factor averaging exactly 1 in linear space) and `Rabbit_Body_Normal_Fur.png` (strand slopes added to the original normals), set as `M_Ziara_Body`'s Base Map and Normal Map. It also switches `M_Ziara_Body` to **`FurBrains/FuzzyLit`** (`Assets/FurBrains/Shaders/FuzzyLit.shader`): URP Lit's own passes (the forward fragment is a copy of URP 17's `LitPassFragment` with one added line; other passes via `UsePass`) plus a lit fresnel "fuzz" rim (`Fuzz Color/Strength/Width`). Its Fuzz values sit outside the per-material buffer, so it isn't SRP-Batcher compatible (fine for one character). Re-copy the fragment if a URP upgrade breaks it. Tune the `k_` constants at the top and re-run. Re-run it after **Create Ziara Materials**, which restores the original textures and URP Lit. `M_Ziara_Body_NoFur` is the original material, for swapping back. (URP Lit's Detail Inputs were tried first and darkened the body, so they're not used.) A parked shell-fur prototype (switched off on the prefab) is also available: the `FurBrains/ShellFur` shader (`Assets/FurBrains/Shaders/`) plus `FurBrainFur`, which at runtime appends one shell material per layer to the Body renderer (extra materials redraw the last sub-mesh). The template material is `M_Ziara_Fur`, created by the materials tool; tune it in Play mode. **Tools → FurBrains → Bake Ziara Fur Mask** (`FurBrainsFurMaskBaker`) writes `Ziara_FurMask.png` limiting fur length to the rest-pose gap under armour, helmet, cape, eyes and mouth. Re-bake after changing Fur Length.
- **`FurBrainsPetBuilder`** (**Tools → FurBrains → Build Ziara Pet Prefab**): generates `FurBrainBasic.controller` (Idle plus Summon/Tap/Feed action states with triggers of the same names; each state plays an empty `Slot_*` sub-asset clip that `FurBrainPet` replaces at runtime via an `AnimatorOverrideController` from its Idle/Summon/Tap/Feed Animation fields, so clips are chosen in the Inspector, not in the controller), `FurBrainBody.mask` (masks out the `root` bone, whose clip keys double up Unreal's axis conversion) and `Prefabs/ZiaraPet.prefab` (the spawner's prefab, fitted to `k_TargetHeight` = 0.6 m tall; rebuilding keeps the Inspector settings of the previous prefab's `FurBrainPet`, `FurBrainMood` and `FurBrainLookAt`; fit transforms live on a `Model` wrapper above the Animator). The pet uses `XRSimpleInteractable` (tap and delete only; the player can't move or scale it). `FurBrainPet` waves on spawn and tap and slowly turns to face the camera. Lockouts: `Tap Cooldown` (player taps ignored for a moment after one) and `Feed Cooldown` (`canEat` false after eating; `FoodMenu.CanBuy` checks it, so food buttons and drag-to-feed grey out meanwhile). Code calling `OnTapped()`/`Celebrate()` directly (minigames) isn't locked out.
- **`FurBrainLookAt`** (on the pet root, added by the pet builder): in `LateUpdate` (after the Animator poses the skeleton) tilts `neck_01`, `neck_02`, `head` up/down so the face points at the camera: it measures the animated head's pitch (face direction recorded from the rest pose in `Awake`) and rotates by the difference, split equally across the bones and clamped; `Angle Offset` fine-tunes. Vertical only: the body's sideways turn is `FurBrainPet`'s.
- **`FurBrainSummoner`** (on the Object Spawner GameObject in the scene): allows one FurBrain at a time by disabling `ARInteractorSpawnTrigger` while one exists. Onboarding (`GoalManager`) stops after the tap-to-place goal; the template's move/scale/rotate hint goals are removed.
- Character folders: `Assets/FurBrains/Models/Ziara/` (Unreal parts, materials, prefab) and `Assets/FurBrains/Models/Wolf/` (Body only). **Animations** are shared by all characters and live in `Assets/FurBrains/Animation/Clips/` (subfolders `Idle/`, `Movement/`, `Talking/`); `FurBrainsAnimationPostprocessor` forces their import settings (no cameras/lights/materials, Generic) and turns on Loop Time for idle, talking, walk and run clips that still use default clip settings. Clips that move the `root` bone (walk/run root motion, the Ziara hop, sitting) lose that movement to `FurBrainBody.mask`. **Tools hard-code these folder and file paths** (`FurBrainsMaterialBuilder.k_Folder`, `FurBrainsModelPostprocessor.k_FixInsideOutParts`, `FurBrainsPetBuilder.k_WaveClipFbx`/`k_IdleClipFbx`), so update them when renaming or moving folders.

- **Lighting:** `CameraKeyLight` (`Scripts/Lighting/`, on the scene's Directional Light) turns the light every frame to shine from over the camera's shoulder (camera yaw + `Side Angle`, fixed `Down Angle`), so the side of the FurBrain the player sees is always lit. With a fixed light, viewing her from the unlit side made her look dark grey-blue. The URP asset has additional lights off (mobile), so there's no separate fill light.

## Pet systems (`Assets/FurBrains/Scripts/Pet/`, `Scripts/UI/`)

- **`PlayerWallet`** (coins) and **`FurBrainNeeds`** live on the scene's `FurBrains Game` object. `FurBrainNeeds` holds two `Need`s (a small serializable class: max, starting, loss per minute, runtime value): **Hunger** (filled by feeding) and **Play** (rises steadily while any minigame is being played: `MinigameRunner.m_PlayPerSecond`, 1.5/s by default, whatever the result; added with `AddPlay(amount, save: false)` each frame and saved once when the game ends); both drain slowly, 0 = empty. **Happiness** = their average (`happinessNormalized`). Both live in the scene, not on the spawned pet, so they survive delete/re-summon. Both save locally with PlayerPrefs. `PlayerWallet` has a `coinsChanged` event; `FurBrainNeeds` has none (the UI reads its values every frame; add events when something needs to react to a change).
- **`FurBrainMood`** (on the pet root, added by the pet builder) owns the facial expression: a base mood from **happiness** bands (`minHappinessPercent`, formerly `minHungerPercent`; default 0–30 % `Sadness`+`SadEar`, 30–60 % neutral, 60–100 % `Empowered`) plus timed reactions (`React`, used by `FurBrainPet.Wave`) and a held face (`Hold(shapes)` / `ReleaseHold()`, e.g. a minigame's expression for its whole length). Priority: reaction > held face > happiness mood. Other code should go through it rather than calling `FurBrainFace.SetShape` for emotions. Ziara's Body shapes: `Blink Squint LipSuck MouthStrech Nose Happy Empowered Surprised Calm Scared Sadness Angry Tired Disgust Contempt A I U E O SadEar` (no "Neutral": that's all emotions at 0).
- **`FoodItem`** ScriptableObjects (`Assets/FurBrains/Food/`, Create → FurBrains → Food Item) hold each food's price, hunger restored and **Crumb Color**. Eating sprays crumbs in that colour: `FurBrainPet.Eat(color)` moves its `Eat Burst` ParticleSystem (a child of `ZiaraPet.prefab`) to mouth height and `Emit`s. **Tools → FurBrains → Set Up Eat Effect** (`FurBrainsEatEffect`) creates `Effects/M_Crumbs.mat` (URP Particles/Unlit, so particle colours show), adds the burst to the pet prefab if missing, and fills any clear Crumb Color with the icon's average non-outline colour; the pet builder also creates the burst.
- **`FoodMenu`** (on the template object menu's `Content`) replaces the shape buttons with one cloned button per food, sorted by price; a food is greyed out with no pet summoned, too few coins, or a full pet. While the food menu is open (`ARTemplateMenuManager.isFoodMenuShown`; closing only slides it down), `FoodMenu` holds the FurBrain's `Pet Expression` (`O` by default) via `FurBrainMood.Hold`, released when it closes. Foods can also be **dragged onto the FurBrain**: `DragToPet` (`Scripts/UI/`, added to each food button by `FoodMenu`) shows the food icon under the finger and, on release over/near the FurBrain (its renderers' screen rectangle plus a margin), runs the same `Buy`; mostly sideways drags are passed to the menu's ScrollRect, and `ARTemplateMenuManager` doesn't auto-close the menu while `DragToPet.isDragging`. **`PetHud`** (top left) shows coins. **`NeedMeter`** shows a need as a liquid fill inside a round button (a "Need Fill" child Image, Filled/Vertical/Bottom with the button's circle sprite, red→green): Hunger in the food button, Play in the minigame button.
- **Tools → FurBrains → Arrange HUD In Open Scene** (`FurBrainsHudLayout`) sets the standard layout (Pet HUD top left, minigame Exit button top right, food and minigame buttons either side of the bottom centre, delete (retry) button to the right of the minigame button with the same edge gap); if those buttons sit in a container (the scene's `Main`), it's stretched to fill the screen so anchors mean screen edges. The template's `Create Button` / `Object Menu Animator` are renamed **`Food Button`** / **`Food Menu Animator`** in the scene; tools look objects up by name and accept both (`FurBrainsFeedingSetup.FindFirstInScene`) and restyles the food and minigame menus' `Cancel Button`s as round X buttons (same look as the minigame Exit button), adds the `Need Fill` meters to the food and minigame buttons and a white `Border` ring (`UI/Icons/Button_Ring.png`) to the food, minigame and delete buttons if missing, and removes the old top-left `Hunger Bar`. Open menus cover the bottom row, so it also adds a **`Need Badge`** to each menu panel (`Object Menu`): a display-only copy of the Food/Minigame button (icon, `Need Fill` meter, ring; Button/PopupMenu and caption removed, no raycasts) beside the menu's X (hunger left in the food menu, play right in the minigame menu), skipped if one exists. The same copy (`CreateNeedBadge`) makes a **`Play Badge`** under the Minigame HUD at the bottom centre, listed in `MinigameHud`'s `Show While Playing` (the counterpart of `Hide While Playing`), so Play is visible during games. It also trims the template's **Options (⋯) menu** (`Options Modal`) to `Visualize Surfaces` plus a **Mute Sounds** row (`Mute Sounds Toggle`, a copy of the surfaces row with `MuteSoundsToggle` and `UI/Icons/Icon_Sound.png`); the hints, remove-all and AR debug rows are switched off, not deleted. Muting is `SoundSettings` (`Scripts/Audio/`, static): `AudioListener.volume` 0/1, saved in PlayerPrefs and applied at start-up via `[RuntimeInitializeOnLoadMethod]`. Both setup tools call it; edit its numbers to change the layout. (Re-running it restyles the menus' Cancel Buttons, overwriting hand tweaks.)
- **Main menu visibility:** `ARTemplateMenuManager`'s `Main Menu` slot (the scene's `Main`: background, food/minigame/delete/dress/options/exit buttons) is shown only while a FurBrain is summoned and no minigame runs. **Onboarding:** `GoalManager` keeps the scan prompt until the plane manager has found a surface (no timer), so "tap to place" only appears once placing is possible; its greeting/options/create references may be empty.
- **Settings sheet:** **Tools → FurBrains → Build Settings Panel In Open Scene** (`FurBrainsSettingsBuilder`, builds only if `Settings Panel` doesn't exist) creates a bottom sheet (layout groups + ContentSizeFitter, mock-up colours as constants) and makes it the menu manager's `Modal Menu`, so the ⋯ button, tap-outside and its X open/close it like the old `Options Modal` (left in the scene, off; the manager still uses its plane slider). `SettingsPanel` (`Scripts/UI/`) wires: Sound effects → `SoundSettings.muted`; Show floor dots → `SetPlanesVisible` / `planesVisible`; Move Ziara → `FurBrainSummoner.Remove()` (tap-to-place returns, needs kept); Scan again → `Remove(false)` + `ARSession.Reset()` + `GoalManager.RestartScanning()` (surfaces ignored for 1 s after); grown-ups `HoldButton` (3 s hold, growing fill, `onHeld` UnityEvent) → `FlutterBridge.ExitToHost`. ## Minigames (`Assets/FurBrains/Scripts/Minigames/`)

- **Module interface:** every game derives from abstract **`Minigame`** (`OnBegin()`, then `FinishWithScore(int)` or `FinishWithOutcome(bool won)`; `Cancel()` for the exit button; `currentScore` shown live by the HUD). Results are `MinigameResult` of kind `Score` or `Outcome`.
- **`MinigameDefinition`** ScriptableObject (Create → FurBrains → Minigame): name, icon, prefab and rewards: coins = `max(minimumCoins, ceil(points × coinsPerPoint))` (`coinsPerPoint` is a float, e.g. 0.5), where won/lost games count a win as 1 point and a loss as 0 (so a loss pays `minimumCoins`).
- **`MinigameRunner`** (on `FurBrains Game`) instantiates the prefab at the summoned pet, calls `Begin`, pays coins via `PlayerWallet.Add`, has Ziara react (`Celebrate()` / `OnTapped()`), destroys the game, plays its `Complete Sound` (clip or Audio Random Container, on an AudioSource on `FurBrains Game` so it isn't cut off with the game) and raises `started`/`ended`. **`MinigameHud`** shows the exit button, live score and results; its optional `Live Score Background` (the scene's `Coin Border`, the live score's parent) is shown and hidden together with the score.
- **Menus:** `IconButtonMenu` is the shared base of `FoodMenu` and `MinigameMenu` (clones the template's menu buttons). Its optional `Label Icon` sprite sits left of each button's bottom label (the food menu uses `UI/Icons/Icon_Coin.png` beside prices; a HorizontalLayoutGroup row keeps icon + text centred). The **Minigame Button** (a copy of the food button) has a `PopupMenu` opening **Minigame Menu Animator** (a copy of the food menu); only one menu is open at a time (`ARTemplateMenuManager.ShowMenu` calls `PopupMenu.HideAll`). Food, minigame and delete buttons hide during a game. Both menu animators use `UI/Animation/FurBrainsMenu.controller` (a copy of the XRI `ObjectMenu` controller whose hide clip moves the panel -500 instead of -335, so a taller menu doesn't poke out when closed). `IconButtonMenu`'s `Bottom Label Raise` lifts the price row (fraction of button height; read at Start). The food menu is the one designed by hand: **Tools → FurBrains → Copy Food Menu Look To Minigame Menu** (`FurBrainsMenuMirror`) copies its RectTransforms, Image/Button/text styling (never texts), active states, animator controller, Menu Scale and Bottom Label Raise onto the minigame menu by matching object paths, duplicates food-only objects (`Feed FurBrain` title → `Play FurBrain`, "Play with Ziara", via `k_Renames`), and leaves the need badges' icons/meters, scripts and runtime buttons alone (Undo-able).
- **Results screen:** `MinigameHud` remembers the finished game; its optional **Play Again Button** calls `MinigameRunner.Play` with it. While results are up a full-screen `Results Backdrop` (made in code in `Awake`, just before the panel, colour `Results Backdrop Color`) dims the game and swallows taps so Main's buttons and the menus can't be pressed.
- **Adding a minigame:** subclass `Minigame` → make a prefab with it on the root → create a `MinigameDefinition` → add it to the `MinigameMenu` list on the minigame menu's `Content`.
- **Base-class helpers** (protected, for every game): `WasTapped(target, radius, ...)` / `TryGetTap` + `IsTapNear` (generous screen-space taps, UI taps ignored), `PetPoint(heightFraction)`, `petHeight`. Pet size everywhere (minigames, crumbs, drag-to-feed) comes from **`FurBrainBounds`** (`Scripts/Character/`, static), which measures mesh renderers only: particle systems on the pet (Eat Burst) have unreliable bounds and once made Ziara measure too tall until her first feed. Timed games set `timeRemaining` / `timeRemainingNormalized`; `MinigameHud` then shows a time bar (negative `timeRemaining` = untimed).
- **Bubble Pop** (`Minigames/BubblePop/`, Score, 30 s timer): bubbles copied from a hidden template child drift from Ziara toward the player and rise; tap to pop (gold = 3 points); they pop by themselves after a while with no penalty. Ziara holds the `O` mouth (`Pet Expression`) for the whole game via `FurBrainMood.Hold`, released in the game's `OnDestroy`. `Pop Sound` (clip or Audio Random Container) plays on each pop; `Golden Pop Sound` replaces it for golden bubbles when set. Pops spray droplets: two ParticleSystem children saved in `BubblePop.prefab` (`Pop Burst`, `Gold Burst`; Mesh render mode using the bubble sphere and bubble/gold material, emission off), made by **Tools → FurBrains → Add Bubble Pop Effects** (also run by the minigame setup; skips ones already linked). At runtime `Burst` moves them, scales their Inspector Start Size and Shape Radius (set for an average bubble) by the bubble's size relative to average, and `Emit`s; half as many droplets when a bubble pops by itself.
- **Cup Shuffle** (`Minigames/CupShuffle/`, Outcome): treat shown under the middle of 3 cups, covered, 5 swaps on half-circle paths, tap a cup; the right cup is always revealed. Rewards 10 for a win, 3 for a loss.
- **Beach Ball Rally** (`Minigames/BeachBall/`): scripted arcs fixed at launch, from Ziara's head toward just below the camera; tap it once it's within Hit Distance to return it; it's a miss when it passes behind the camera or reaches the floor; score = rally length.
- **Copy Ziara** (`Minigames/CopyZiara/`, Score): a Simon-style memory game. Coloured pads (count = shorter of `Pad Colors`/`Pad Notes`) lie on an arc in front of the FurBrain, sized as fractions of `petHeight`; it plays a sequence (pad glows via emission on per-pad runtime materials, lifts, plays its note), the player repeats it, each round adds a step and plays faster. A wrong tap plays a low boop, flashes the right pad and ends the game; score = longest sequence copied (max `Max Length`).
- **Sound:** `ToneGenerator` (`Scripts/Audio/`, static) makes notes in code (`AudioClip.Create`, sine + second harmonic, attack/decay envelope); no audio files yet. Games play them through an `AudioSource` on the game root (2D). Runtime clips and materials are destroyed in the game's `OnDestroy`. Imported sounds can be an `AudioClip` or a Unity 6 **Audio Random Container** (random clip/pitch/volume): fields that should accept both are typed `AudioResource` (e.g. `FurBrainPet.m_EatSound`); clips play with `PlayOneShot`, containers by setting `AudioSource.resource` and calling `Play()` (on a separate AudioSource so they don't cut off other sounds).
- **Tools → FurBrains → Set Up Minigames In Open Scene** (`FurBrainsMinigameSetup`) creates the assets for all four games (keeping existing ones), runner, HUD (including the time bar), button and menu copies, and adds missing games to the menu list (run the feeding setup first).

## Flutter embedding (Unity as a Library)

The FurBrains parent app is Flutter (`github.com/3PM-Source/furbrains-parent-app`, cloned locally to `C:\Users\Decoded\FurBrainsParentApp`; not modified yet). The game is embedded with the community plugin **flutter_embed_unity 2.0.0**: its Unity half is the git package `com.learntoflutter.flutter_embed_unity_6000_0` in `Packages/manifest.json` (`SendToFlutter.Send`, **Flutter Embed → Export project to Flutter app** menu); its Flutter half comes from pub.dev.

- **`FlutterBridge`** (`Scripts/Integration/`, on `FurBrains Game`): every message is JSON `{"type":…,"coins":N,"food":0..1,"fun":0..1}` (food = Hunger, fun = Play). Types: `ready` at start, `coins` on `PlayerWallet.coinsChanged`, `needs` when food or fun moved ≥ 1 % (polled in `Update`, as `FurBrainNeeds` has no event) and on pause, `exit` from **`ExitToHost()`** (the exit button's On Click; does nothing without a host). Flutter calls `SetNeeds('{"food":…,"fun":…}')` (→ `FurBrainNeeds.SetLevels`) and `AddCoins('10')` with `sendToUnity('FurBrains Game', …)` (found by GameObject + method name at runtime, so don't rename either). `SendToFlutter` only logs in the Editor and throws in a standalone APK, so the bridge catches that once and stops sending (`hasHost`).
- **Parent app integration** (local branch **`UnityGameEmbed`** in `C:\Users\Decoded\FurBrainsParentApp`, pushed to their GitHub as branch `UnityGameEmbed`; no PR or merge into their `main` until the user says so): same Android setup as `FlutterHost` (their `MainActivity` keeps its BLE provisioning channels), `minSdk` 26, NDK r27c via `ndkVersion` (Gradle downloads it). `/ar` (Play in AR, Visit in AR, Kids Zone game tiles) opens `lib/features/kids_zone/presentation/unity_ar_screen.dart` on Android, the placeholder on iOS/web. Per-child food/fun are saved in SharedPreferences (`pet_status_providers.dart`, keys `pet_needs.<childId>.food/fun`, new pet 0.8 = Unity's starting 80); the screen sends them on `ready` (first visit) or on open (Unity stays loaded), saves `needs`, and pops on `exit`. Their project needs **Flutter 3.44.6** (`C:\Users\Decoded\develop\flutter-3.44.6`; 3.50 rejects their Gradle 8.10) and Windows Developer Mode (symlinks). Export Unity into `FurBrainsParentApp/android/unityLibrary` (git-ignored). Open before merging: iOS (the plugin's iOS half needs a Unity iOS export), how teammates get the export, Unity coins vs their Spark Coins, game tiles don't pick a minigame yet.
- **`FlutterHost/`**: a stand-in Flutter test app (`com.decoded.furbrains_host`): Home shows coins, "Play" opens `EmbedUnity`, "+10 coins" tests Flutter → Unity. Works on the Galaxy S7 (Android 8).
- **Export workflow:** Unity Player settings must have Application Entry Point = **Activity** and ARMv7 + ARM64; tick **Export Project** in Build Profiles (untick it for a normal Build And Run). Export into `FlutterHost/android/unityLibrary` (git-ignored, regenerated) **after every Unity change**, then `flutter run` from `FlutterHost/`. Flutter 3.50 is at `C:\Users\Decoded\develop\flutter`.
- **Host Android setup** (needed in the parent app too): `include(":unityLibrary")` + `":unityLibrary:xrmanifest.androidlib"` in settings.gradle.kts, a `flatDir` for `unityLibrary/libs`, `implementation(project(":unityLibrary"))`, `minSdk = 26`, Unity's NDK r27c via `ndkPath`, `noCompress` for Unity data, `unityStreamingAssets=` in gradle.properties, the full `configChanges` list.
- **Android ≤ 12 fix (plugin issue #21):** with `FlutterActivity`, AR stays blank (`NoClassDefFoundError: android/window/BackEvent`). `MainActivity` extends `FlutterFragmentActivity` and implements `IFakeUnityPlayerActivity` with a public `@JvmField mUnityPlayer`, and the manifest sets `android:enableOnBackInvokedCallback="false"`. A future Flutter update could break this.
- **Limits:** one Unity instance per app, staying in memory once loaded; the plugin's iOS half targets Unity 2022.3, so iOS with Unity 6 is unverified. The parent app's coins are server-side, unlike the local `PlayerWallet`: which is authoritative is still to be decided.
- The Unity splash screen is switched off (allowed on all plans since Unity 6).

## Code layout and conventions

- `Assets/Samples/XR Interaction Toolkit/3.5.1/` is **imported sample code** in its own assemblies (`ARStarterAssets.asmdef`, `StarterAssets.asmdef`). Avoid editing it in place, because re-importing the sample overwrites it. Copy a script or subclass it into project code instead.
- `Assets/MobileARTemplateAssets/` is template code compiled into `Assembly-CSharp` (namespace `UnityEngine.XR.Templates.AR`). It's fine to modify.
- Put new prototype code under its own folder (for example `Assets/FurBrains/`), not inside the sample or template folders.
- Code that references AR Foundation inside the XRI sample assemblies is wrapped in `#if AR_FOUNDATION_PRESENT`.
- **UI reads game state every frame** (like UMG property bindings): HUD scripts hold references to the systems that own the data (`PlayerWallet`, `FurBrainNeeds`, `MinigameRunner`) and read them in `Update`, rebuilding text only when a value changed. Systems never reference the UI. C# events are kept for one-off moments that carry data (e.g. `MinigameRunner.ended` for the results panel).
- Code style follows the template: `[SerializeField] T m_Field;` private fields with a `[Tooltip]` and a public property; subscribe in `OnEnable` and unsubscribe in `OnDisable`.
